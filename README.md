- 🍲 **٧٢ وصفة جديدة** (١٩٦ الآن) و٣ أقسام جديدة: 🥤 مشروبات وعصائر، 🎒 لانش بوكس المدرسة، 🥗 صحي ودايت. تصفّح الوصفات حسب القسم

**🏠 البيت**
- 🔍 **بحث شامل** (زر العدسة أعلى الرئيسية): الوصفات، الدليل، المهام، القوائم، الملاحظات، المصاريف والأرقام. يقبل «قهوه» و«قهوة» معاً

- 🛒 **قائمة التسوق مرتبة حسب أقسام السوق**، وزر **«سجّل المشتريات كمصروف»** يضيف المبلغ لمصاريف اليوم مباشرة (مع «تراجع»)
- 🧺 رموز الغسيل على الملابس (الحوض، المبيّض، التجفيف، الكي، التنظيف الجاف)
- 📋 ٥ قوائم جاهزة جديدة: تنظيف المطبخ العميق، روتين قبل النوم، صباح المدرسة، تجهيز الشتاء، تجهيز الصيف
- 💾 تذكير لطيف بحفظ نسخة احتياطية إذا مر أسبوعان بدون نسخة
- ⏱️ ٤ مؤقتات جديدة، ١٠ أطعمة في جدول الحفظ، ٣٠ نصيحة و٣٠ رسالة يومية جديدة، وإنجازان جديدان
- 🤖 أندرويد: الاتصال يفتح لوحة الاتصال مباشرة، والشاشة تبقى مضاءة في وضع الطبخ. **بدون أي أذونات جديدة**

## 🔁 تحديث موقعك على GitHub (أي نسخة كانت لديك)
1. فك ضغط `bayti-update-v4.2.zip`.
2. في المستودع: **Add file ← Upload files**، واسحب **كل** ما بداخله (الملفات + مجلدَي `src` و`android`)، ثم **Commit changes**.
   - من الموبايل: ارفع الملفات من الصفحة الرئيسية للمستودع، ثم افتح مجلد `src` وارفع ملفاته الثلاثة **من داخله**. ملف `android/src/com/bayti/home/MainActivity.java` يلزم فقط إن كنت تبني التطبيق تلقائياً من GitHub: افتح الملف نفسه في المستودع ← ✏️ واستبدل محتواه.
3. انتظر دقيقتين، ثم افتح الموقع وأغلقه وافتحه مرة ثانية.
4. للتأكد: **الإعدادات ⚙️** ← في الأسفل يجب أن يظهر **«الإصدار 4.2.0»**.

## 🚀 طريقة النشر الجديدة (مرة واحدة فقط — ١٠ دقائق)

> الفكرة: أنت ترفع **الكود المصدري** فقط، وGitHub يبني الموقع وينشره تلقائياً
> بعد كل تعديل. لا حاجة لرفع ملفات الموقع يدوياً بعد الآن.

### ١) ارفع الملفات
1. فك ضغط `bayti-source-github.zip` على جهازك.
2. افتح مستودعك `bayti` على GitHub (أو أنشئ مستودعاً جديداً **Public** بنفس الاسم).
3. إذا كان فيه ملفات النسخة القديمة: احذفها (أو أنشئ مستودعاً جديداً — أسهل).
4. اضغط **Add file ← Upload files**، واسحب **كل محتويات** المجلد الذي فككته
   (بما فيها المجلد `.github`) إلى الصفحة، ثم **Commit changes**.

> ⚠️ **مهم:** المجلد `.github` مخفي على ماك (اضغط `Cmd + Shift + .` لإظهاره).
> للتأكد: في صفحة المستودع يجب أن ترى مجلد `.github`. إن لم يظهر، راجع «حل المشاكل» بالأسفل.

### ٢) فعّل النشر التلقائي
1. **Settings ← Pages**
2. تحت **Build and deployment ← Source** اختر **GitHub Actions** (بدلاً من Deploy from a branch).
3. افتح تبويب **Actions** ← ستجد «نشر الموقع» يعمل ⏳ ← بعد دقيقة يصبح ✅.

🎉 الرابط كما هو: `https://USERNAME.github.io/bayti/`

### ٣) (اختياري) تطبيق أندرويد تلقائي
ليبني GitHub ملف APK موقّعاً بنفس مفتاحك وينشره في صفحة **Releases**:

1. **Settings ← Secrets and variables ← Actions ← New repository secret**
2. أضف سرّين:

| الاسم | القيمة |
|---|---|
| `KEYSTORE_B64` | محتوى الملف `android/keystore/KEYSTORE_B64.txt` (من النسخة الخاصة التي عندك، انسخه كاملاً) |
| `KEYSTORE_PASS` | محتوى الملف `android/keystore/password.txt` |

3. **Actions ← بناء تطبيق أندرويد ← Run workflow**.
4. بعد ٢–٣ دقائق ستجد `bayti.apk` في صفحة **Releases**، وسيظهر زر «حمّل تطبيق أندرويد»
   تلقائياً داخل إعدادات الموقع.

> 🔒 الأسرار (Secrets) مشفّرة في GitHub ولا يراها أحد، حتى في المستودع العام.
> ملفات المفتاح نفسها **لا تُرفع أبداً** (وهي غير موجودة في ملف الكود المصدري).
> تحميل رابط ثابت لآخر إصدار: `https://github.com/USERNAME/bayti/releases/latest/download/bayti.apk`

## 🔄 كيف أضيف محتوى أو تحديثاً؟ (من المتصفح أو الموبايل)

1. افتح `data.json` في المستودع ← اضغط ✏️ (Edit).
2. أضف رسالة / نصيحة / وصفة بنفس شكل الموجود.
3. **زوّد رقم `"rev"` بواحد** (مثلاً `2` ← `3`) — هذا ما يجعل الأجهزة تجلب المحتوى الجديد.
4. **Commit changes** ← خلال دقيقة يُنشر تلقائياً ✅.

المستخدمون يحصلون على المحتوى الجديد في المرة القادمة التي يفتحون فيها التطبيق.
إذا أخطأت في الكتابة (فاصلة ناقصة مثلاً)، سيتوقف النشر بعلامة ❌ ويخبرك بالخطأ —
**ولن يتأثر الموقع الحالي**.

### إصدار جديد من التطبيق
- غيّر `"version"` في `data.json` (مثلاً `4.2.0`) وأضف سطور `"changelog"`.
- للأندرويد: **Actions ← بناء تطبيق أندرويد ← Run workflow** — سيتعرّف عليه الهاتف كتحديث.

## 🗂️ محتويات المستودع

| المسار | الوظيفة |
|---|---|
| `data.json` | كل المحتوى: رسائل، نصائح، وصفات، مهام، خطط جاهزة، سجل التغييرات |
| `src/` | واجهة التطبيق (HTML / CSS / JavaScript) |
| `build.py` | يجمع كل شيء في موقع واحد داخل `site/` |
| `android/` | تطبيق أندرويد (WebView آمن بدون صلاحيات) |
| `.github/workflows/deploy.yml` | النشر التلقائي على GitHub Pages |
| `.github/workflows/android.yml` | بناء وتوقيع APK ونشره في Releases |

تجربة محلية (اختياري): `python3 build.py` ثم افتح `site/index.html`.

## 🛠️ حل المشاكل

**المجلد `.github` لم يُرفع؟** أنشئ الملفات يدوياً:
**Add file ← Create new file** ← اكتب الاسم `.github/workflows/deploy.yml` بالضبط
← الصق محتوى الملف من جهازك ← Commit. كرر ذلك مع `android.yml`.

**الرابط يعطي 404؟** تأكد أن Source = **GitHub Actions** وأن آخر تشغيل في Actions ✅.

**❌ في Actions؟** اضغط عليه لترى السبب (غالباً خطأ كتابة في `data.json`).

**التطبيق لا يظهر التحديث؟** أغلق التطبيق وافتحه مرة أخرى؛ سيظهر شريط «يوجد تحديث».

- لا تسجيل، لا سيرفر، لا إعلانات، لا تتبع. البيانات في `localStorage` على جهازك.
